# Проверка адаптации без повторного подбора по прежнему тесту

4 ноября 2026 выполнены шесть новых LoRA-обучений и оценка на 24 беременных
из открытого HRV29. Улучшены процедура выбора и проверяемость эксперимента.
Устойчивого выигрыша точности от адаптации не получено; рабочей остаётся
исходная Chronos-2. API автоматически не переключается.

## Данные и границы проверки

Источник: [HRV and salivary cortisol data in pregnant women](https://zenodo.org/records/7102622),
DOI 10.7280/D12Q4P, CC0. Это международный исследовательский набор; он не
является выгрузкой российской медорганизации или набором Минздрава РФ.
SHA-256 Excel: `bed2512b7b99c9a4c69f4c6fe61e3a698abe53208fe36e602755edfca4b3ac8a`.
Подготовка и ограничения описаны в [finetuning.md](finetuning.md).

Используются только материнская ЧСС и подходящие непрерывные контрольные
визиты: одна запись на женщину, шаг 5 минут, история 30 минут, цель 60 минут.
Кортизол, HRV и метки стресса не поступают в модель. Нет проверки других
датчиков, осложнений, домашнего мониторинга или суточной истории API.

Ранее просмотренные пять тестовых женщин полностью исключены из этого
исследования. Оставшиеся 20 train и 4 validation образуют development-когорту
из 24 женщин. Это внутренняя исследовательская оценка после первого
эксперимента, а не новая внешняя клиническая валидация. Показатель 3,87 ниже
прежних 4,51 на другой группе, но такое сравнение не доказывает улучшение.

## Что изменено

1. **Разделение по женщинам.** Три внешние группы по восемь участниц.
   Для каждой группы остальные 16 разделяются на 12 для обучения и 4 для
   внутреннего выбора. Внутри конкретного обучения эти группы не пересекаются.
   Каждая из 24 женщин оценивается во внешней группе ровно один раз.
   Внутренний выбор использует отдельную отложенную группу, не полный inner CV.
2. **Новый старт каждого обучения.** Все шесть адаптеров начинаются от
   исходной зафиксированной Chronos-2. Первый адаптер HRV29 не используется:
   он уже видел часть женщин, которые здесь оказываются во внешних группах.
3. **Равный вес женщин.** В `study` обучающий sampler получает по одной полной
   записи на женщину и выбирает записи равновероятно. Длинная запись больше
   не получает дополнительный вес из-за числа заранее нарезанных окон.
   Это изменение относится к `study`; историческая нарезка `finetune` сохранена.
4. **Checkpoint по целевой ошибке.** Проверка каждые 25 шагов; выбирается
   минимальная MAE медианного прогноза на внутренней validation. При нескольких
   сегментах ошибки сначала усредняются по женщине. Значения будущего
   используются только для подсчёта ошибки, контекст прогноза их не содержит.
   В первой внешней группе выбран checkpoint-25, хотя training loss снижался
   дальше. Новый критерий также стал значением по умолчанию у `finetune`.
5. **Ограниченный выбор адаптации.** Rank 4, alpha 8; learning rate 1e-5 или
   5e-5; 100 шагов, batch 4. Проверяются веса адаптера 0,25 / 0,5 / 1,0
   в смеси с исходной моделью; смешиваются одноимённые квантили.
   Допускается исходная модель без адаптации. Кандидат должен снизить
   среднюю по женщинам MAE минимум на 1% и улучшить минимум половину женщин
   внутренней validation. Это инженерное правило, не медицинский порог и не
   критерий статистической значимости. Среди прошедших выбирается минимальная MAE.
6. **Аудит.** План с разбиениями записывается до загрузки модели; сохраняются
   его SHA-256, история ошибок, выбранные checkpoints и контрольные суммы
   адаптеров. Проверяются завершение обучения, изменение только LoRA-параметров
   и неизменность исходной модели. Cross-learning между женщинами выключен.

Настройки и решение о смеси фиксируются по внутренней validation до
прогнозирования соответствующих внешних женщин. По опубликованным внешним
ошибкам новый перебор настроек в этом запуске не выполнялся.

## Фактический результат

Каждый метод оценён на одинаковых **24 женщинах и 288 будущих точках**:
по 12 шагов на женщину. Поэтому здесь точечная MAE совпадает со средним
из индивидуальных MAE. Единица независимого наблюдения — женщина.

| Метод | MAE, уд/мин | RMSE, уд/мин | Покрытие p10–p90 |
|---|---:|---:|---:|
| Исходная Chronos-2 | 3,8679 | 5,0593 | 96,53% |
| Процедура выбора адаптации | 4,0343 | 5,3212 | 93,75% |
| Последнее значение | 4,1097 | 5,8538 | — |
| Среднее доступной истории | 4,3028 | 5,4652 | — |

| Внешняя группа | Выбор на внутренней validation | MAE базы | MAE выбранного варианта |
|---|---|---:|---:|
| 1 | Исходная модель | 3,2163 | 3,2163 |
| 2 | LoRA rank 4, LR 5e-5, вес 1 | 3,4680 | 3,9675 |
| 3 | Исходная модель | 4,9193 | 4,9193 |

Средняя разница MAE «процедура минус база» равна **+0,1665 уд/мин**.
Парный bootstrap по женщинам, 2000 повторов: условный 95%-й процентильный
интервал **[−0,0256; +0,4285]**. Он включает ноль и не подтверждает устойчивого
выигрыша. Модели внутри bootstrap не переобучаются; интервал условен на
обученных внешних группах и не охватывает всю вариативность обучения.

Покрытие интервала с номиналом 80% выше номинального: у базы средняя ширина
24,77 уд/мин, у процедуры 22,77. Большое покрытие само по себе не означает
хорошую калибровку. Медицинская пригодность не проверялась.

Шесть обучений по 100 шагов и вся оценка заняли **155,06 с** с загрузкой
закешированной модели на CPU, 4 потока, float32. В каждом адаптере 603 456
обучаемых параметров. Это замер малого набора на текущей машине, не оценка
срока обучения на будущей медицинской выгрузке.

Полный сводный отчёт с ошибками по горизонтам и аудитом каждого обучения:
[results/hrv29_study_v2.json](results/hrv29_study_v2.json).
Оценивается процедура выбора, которая может выбирать разные модели в разных
группах. Единого нового готового к применению checkpoint этот запуск не создаёт.

## Воспроизведение

После установки `.[finetune,test]` и подготовки `data/hrv29`:

```powershell
.\.venv\Scripts\python.exe -m pregnancy_monitor study --dataset data/hrv29 --output-dir outputs/hrv29_study_v2 --steps 100 --cpu-threads 4 --seed 20261104
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Linux/macOS: заменить путь к Python на `.venv/bin/python`. Флаг `--offline`
позволяет использовать заранее закешированную ревизию. Каталог результата
должен быть новым или пустым. Ревизия модели и версии зависимостей те же,
что в первом эксперименте; они также записаны в JSON.

В каталоге запуска сохраняются `study_plan.json`, `progress.json`, `report.json`,
`development_oof_predictions.csv` и шесть каталогов обучения с адаптерами.
В Git публикуются код и агрегаты; индивидуальные записи, прогнозы и веса
остаются вне репозитория. Модель в API и профиль суточной истории не изменены.

## Следующий эксперимент

До новых данных сохраняем исходную Chronos-2 как точку сравнения. После
получения выгрузки медорганизации сначала проверяем формат, качество,
устройства, сроки беременности и доступную длину непрерывных записей.
Новые разбиения и критерии фиксируем до обучения; резервируем новую
непросмотренную группу для окончательной оценки. Сравниваем старт с исходной
модели и продолжение HRV29 на одинаковых медицинских данных. Изменение
клинических правил и порогов требует отдельного согласования и проверки;
данный эксперимент обучает числовой прогноз ЧСС.
