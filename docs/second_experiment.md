# Второй эксперимент — 4 ноября 2026

## Что изменилось

Расширена оценка готовой Chronos‑2 и добавлен приватный серверный API. Веса
модели не менялись. Реальных измерений беременных и дообучения в этом этапе нет.

## Условия сравнения

Для каждого из четырёх сценариев генератор создаёт 2 ряда по 3 дня с seed 42.
Шаг — 5 минут; история — 288 наблюдений; прогноз — 12 точек / 60 минут.
Проверяются последние 12 непересекающихся часовых окон каждого ряда:
288 отложенных точек на сценарий для каждого из четырёх методов.
На каждом окне все методы получают одну и ту же предшествующую историю.

Среда: Python 3.12.14, Linux, CPU с 2 потоками; chronos-forecasting 2.3.2,
transformers 4.57.6, torch 2.8.0+cpu, numpy 2.3.5, pandas 2.2.3.
Ревизия весов: `29ec3766d36d6f73f0696f85560a422f50e8498c`.

## Фактические результаты

Все ошибки в таблице — MAE в уд/мин. Меньше — лучше.

| Сценарий | Chronos‑2 | Последнее значение | Среднее за час | Предыдущий день | Покрытие p10–p90 |
|---|---:|---:|---:|---:|---:|
| Суточная кривая | 1,617 | 1,609 | 1,865 | 1,669 | 76,7% |
| Тренд | 1,635 | 1,608 | 1,879 | 3,506 | 78,1% |
| Сдвиг уровня | 1,709 | 1,671 | 2,576 | 4,096 | 76,7% |
| Шум | 4,134 | 4,238 | 4,160 | 4,503 | 74,7% |

На первых трёх сценариях лучший простой метод получил меньшую MAE. На шумном
ряду преимущество Chronos‑2 над лучшим простым методом составило около 0,6%.
Такой небольшой результат на фиксированной синтетике не доказывает устойчивого
преимущества. Параметры и синтетика не подбирались для изменения победителя.
Номинальный 80%-й интервал покрыл примерно 75–78% точек этих примеров.

Результат первого эксперимента с тремя окнами нельзя напрямую сравнивать с этой
таблицей как улучшение модели: здесь расширены проверочные окна и сценарии.
Полные числа, настройки, модель и хеши входов: [second_experiment.json](second_experiment.json).

## Проверка сервиса

- 28 автоматических тестов: CLI, базовые прогнозы, отсутствие утечки будущего,
  метрики, схема API, авторизация, качество и давность истории, лимиты, параллельные запросы.
- Настоящий HTTP-запрос через Uvicorn к Chronos‑2 на CPU: получены 12 точек
  с конечными и упорядоченными p10/p50/p90. Веса загружены из локального кэша.
- Такой же сценарий с `persistence`: явная пометка базового метода и `null` вместо интервалов.
- Проверены отказ до вычисления на плохих данных, 429 при занятости и 503
  при сбое модели без автоматической подмены прогноза.
- Проверено, что 576 принятых наблюдений сокращаются до последних 288 на входе модели;
  более длинный запрос отклоняется.

Сервис и benchmark работают. Датчик VivaLNK, его SDK и реальная физиологическая
выборка ещё не подключены; медицинская валидация не проводилась.

## Как повторить

Установите окружение по README. Для каждого сценария `daily`, `trend`, `shift`, `noisy`
выполните следующие команды, заменив имя сценария и пути:

```powershell
.\.venv\Scripts\python.exe -m pregnancy_monitor generate --scenario daily --output data/daily.csv
.\.venv\Scripts\python.exe -m pregnancy_monitor benchmark --input data/daily.csv --folds 12 --data-kind synthetic --output-dir outputs/daily
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/demo_api.py --start-server --backend chronos2
```

Для запуска из уже скачанных весов benchmark принимает `--offline`.
Подробности: [benchmark.md](benchmark.md), [api.md](api.md), [план развития](development.md).
