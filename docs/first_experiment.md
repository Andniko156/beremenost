# Проверка первого эксперимента — 29 октября 2026

## Что проверено

- Установка пакета через `python -m pip install -e '.[chronos]'`.
- Все 12 тестов: `python -m unittest discover -s tests -v`.
- Реальная загрузка `amazon/chronos-2`, а не заглушка или случайный прогноз.
- Прогноз для 2 синтетических рядов: 24 строки, по 12 будущих точек на ряд,
  конечные и упорядоченные p10 / p50 / p90.
- Последовательная проверка на 3 отложенных часовых окнах на ряд:
  72 точки для Chronos‑2 и те же 72 точки для простого прогноза.
- Автономный режим с уже загруженной моделью, `--offline`.

## Конфигурация

Python 3.12.14, Linux x86_64, CPU, 2 вычислительных потока.
Библиотеки: chronos-forecasting 2.3.2, transformers 4.57.6,
torch 2.8.0+cpu, numpy 2.3.5, pandas 2.2.3.
Ревизия весов: `29ec3766d36d6f73f0696f85560a422f50e8498c`.

Вход получен командой `python -m pregnancy_monitor generate`:
2 ряда × 3 дня × 288 точек, seed 42, всего 1728 строк.
SHA-256 входного CSV:
`95a0d896f8453fd290133cd5868d0a786d7f998a68625b51c9fb7e762ee1f411`.
Шаг 5 минут, история 288 точек, горизонт 12 точек / 60 минут.

Для ограничения числа вычислительных потоков использованы переменные
`OMP_NUM_THREADS=2` и `MKL_NUM_THREADS=2`.
В PowerShell их можно установить перед запуском:

```powershell
$env:OMP_NUM_THREADS = "2"
$env:MKL_NUM_THREADS = "2"
```

Это настройки воспроизведения данного замера, а не требование модели.
Замер включает загрузку модели в память и вычисление; универсальная оценка
производительности для VPS по нему не делается.

## Результат на синтетике

| Прогноз | MAE, уд/мин | RMSE, уд/мин | Покрытие p10–p90 | Средняя ширина интервала, уд/мин |
|---|---:|---:|---:|---:|
| Chronos‑2 | 1,649 | 2,203 | 75% | 4,946 |
| Последнее значение | 1,546 | 1,952 | Не рассчитывается | Не рассчитывается |

Простой прогноз оказался точнее на этой небольшой фикстуре. Доказательств
преимущества Chronos‑2 здесь нет. Фактическое покрытие 75% относится к этим
72 точкам; номинальные 80% не являются гарантией на новых данных.

Проверен вычислительный путь и формат результата. Качество для реального
мониторинга беременности не оценивалось. Подбирать синтетику ради победы модели
или обучать на ней медицинский прогноз не следует. Следующий содержательный
этап — согласованные измерения с подтверждённым качеством и честная оценка
на отложенных наблюдениях и участницах.
